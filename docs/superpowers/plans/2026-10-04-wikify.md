**Goal:** ship a `wikify` kit + repo-level `vibe wikify` commands that build a citation-verified wiki in `docs/wiki/` and gate `git push` (Claude Code, Codex, Cursor) until the wiki is fresh.

**Architecture:** two pieces. (1) Repo engine `agents/wikify/` (stdlib, pure, git via fixed argv): state, citations+verifier, secret scan, extractor/plan, init, CLI glue. (2) Home-level kit `agents/kits/wikify/`: a standalone push-gate hook script + installer modeled on guardrails. LLM prose is written by the agent following `docs/wiki/WIKIFY.md` (created by `init`); the kit itself has no LLM, network, or telemetry.

**Tech Stack:** Python 3.10+ stdlib, `unittest`, git CLI.

**Spec:** `docs/superpowers/specs/2026-10-04-wikify-design.md` (uncommitted; commit it first, see Task 0).

## Global Constraints
- Python 3.10+, stdlib only, 4-space indent, no new dependencies.
- Hook scripts run standalone: they must NOT import `agents`.
- `agents/cli.py` must not import concrete kit installers (`tests/test_kit_registry.py` asserts this); it may import `agents.wikify.commands`.
- Dry-run paths side-effect free; installer preserves user files unless manifest proves ownership.
- Kit manifest `kit: "wikify"`, managed files under `templates/wikify/`; manifest dir `~/.vibe-wikify/`.
- Wiki paths staged with `git add -- docs/wiki` only. Citations: repo-relative `path:line` only. Hook stderr static.
- Commit style: Conventional Commits, scope `wikify`; end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Run tests: `python3 -m unittest discover -s tests` (focused: `python3 -m unittest tests.test_wikify_<x>`).

## Review Focus (failure modes the spec implies; each pinned by a test in the owning task)
1. First `git push -u` on a new branch / no upstream: hook must not depend on `@{u}` (Task 7).
2. After docs commit, push must pass (docs-only diff since the state-file commit) — no infinite block (Tasks 2, 7).
3. Rebase / squash-merge / cherry-pick: freshness derives from the state file's commit history, so a rewritten SHA never forces a rebuild; marking twice at different HEADs must change the file or the base never advances and the hook blocks forever (Tasks 2, 6, 7).
4. Citation to untracked / working-tree-only / secret-path / absolute / `..` path rejected (Task 3).
5. Wiki text that quotes a secret passes citation check but is caught by scan (Task 4).
6. Hand-edited human block containing a bad citation or secret-shaped text: citations skipped, scan still applies (Tasks 3, 4).
7. `git push --delete`/no commits yet: hook allows (Task 7).

## `docs/wiki/.wikify.json` schema (version 1) and base selection — REVISED after advisor review
`{"version":1,"covered":<HEAD sha at last mark|null>}` — informational only; `mark` MUST rewrite the file every run (value changes with HEAD), because the base is derived from path history, not from the stored SHA:

**base = `git log -1 --format=%H -- docs/wiki/.wikify.json`** (the commit that last touched the state file). **Fresh** iff the state file exists, base exists (state file committed), and `git diff --name-only <base>..HEAD` touches only `docs/wiki/**`. Survives rebases, squash merges, cherry-picks (a stored SHA would not: every `git pull --rebase` would force a full rebuild). No `pages` map is committed (fewer merge conflicts across parallel branches); the page→cited-files map is derived from citations on demand (`citations.index(root) -> dict[page, set[path]]`). `WIKIFY.md` tells the agent: on a `.wikify.json` merge conflict take either side then rerun `vibe wikify mark`.
- State file never committed yet (just `init`ed, or untracked) → base None → stale / full build.
- Config files live under `docs/wiki/` so teammates share them: `docs/wiki/.wikifyignore` (path globs) and `docs/wiki/.wikify-allow` (escape hatch for scan false positives: lines of `<page-rel>|<exact matched text>`, shown in the confirmation gate).

### Task 2: gitview + state + freshness
**Files:** Create `agents/wikify/gitview.py`, `agents/wikify/state.py`; Test `tests/test_wikify_state.py` (temp git repos via `subprocess.run(["git",...], cwd=tmp)` with `-c user.name=t -c user.email=t@t`).
**Produces:**
- `gitview.run_git(root: Path, *args: str) -> subprocess.CompletedProcess` (fixed argv list, `shell` never, `text=True`, `check=False`, `timeout=10`; `TimeoutExpired` → result with returncode 124)
- `gitview.repo_root(cwd) -> Path|None`, `head(root) -> str|None`, `tracked_files(root) -> list[str]` (`git ls-files` — tracked in index/HEAD; see note), `show_head(root, rel) -> str|None` (`git show HEAD:<rel>`), `last_commit_touching(root, rel) -> str|None` (`git log -1 --format=%H -- <rel>`), `changed_since(root, base) -> list[str]|None` (`git diff --name-only base..HEAD`; None on error), `deleted_since(root, base) -> list[str]` (`--diff-filter=D`).
- `state.load(root) -> dict` (missing/invalid/non-object → `{"version":1,"covered":None}`; untrusted JSON: validate types), `state.save(root, head)` (always rewrites `covered`), `state.base(root) -> str|None` (= `last_commit_touching(root, "docs/wiki/.wikify.json")`), `state.is_fresh(root) -> bool`.
```python
def is_fresh(root):
    h = gitview.head(root)
    if h is None: return True            # no commits: nothing to push/cover
    base = state.base(root)              # commit that last touched .wikify.json
    if base is None: return False        # never committed -> stale
    changed = gitview.changed_since(root, base)
    return changed is not None and all(p.startswith("docs/wiki/") for p in changed)
```
